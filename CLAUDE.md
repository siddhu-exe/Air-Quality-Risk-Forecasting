## Working rules (standing, set by the owner 2026-10-15)

**Workflow**
- Trunk-based: commit directly to `main`. Create a branch only when truly needed (a risky or long-running change that would break `main`) and say why before creating it. Merge it back and delete it (locally and on `origin`) as soon as it is done.
- Before every commit: run the full test suite (`./venv/bin/python -m pytest`, plus `cd frontend && npm test` when the frontend changed) and show the owner the staged file list and a short message. Small, focused commits with conventional-commit messages (`feat`/`fix`/`docs`/`refactor`/`chore`/`test`). Explicit paths, never `git add -A`.
- Push to `main` after each commit once the owner has OK'd it. Never force-push `main`.
- One checkout, no worktrees unless the owner asks.
- Ask before: pushing, merging, creating cloud resources, deleting files or branches that are not already merged. Bulk discards (`git clean`, `git stash drop`) may be refused by the permission layer; the owner can run them with `!`.

**Production standard**
- Treat this as a production project, not a coursework repo: clean structure, clean code, accurate docs, no stale or duplicate files, no internal working notes in public docs. Every number in a doc comes from a script output.
- Local machine is old and crashes under load: run heavy work (training, big matrix builds) on Colab, keep local runs single-threaded and low priority (`OMP_NUM_THREADS=1 nice -n 19`), one job at a time.

## What this is

Delhi air quality risk forecasting: 1h/6h/24h AQI forecasts across 7 CAAQMS stations, CPCB/GRAP risk classification with cost-sensitive alert thresholds, and a Diwali-ban causal (ITS/placebo) analysis. The project is a sequence of phases (ETL → EDA → features → modeling → classification), each leaving artifacts on disk that later phases and the UIs consume. `README.md` has results and background; `docs/` and `reports/**/*.md` hold per-phase findings and specs.

## Pipeline and data flow

1. **ETL** (`etl/`): raw CPCB/DPCC spreadsheets in `Og Data/` → `discover.py` → `transform_caaqms.py` / `transform_aqi.py` (header mappings in `schemas.py`) → idempotent load into PostgreSQL 16 (`load_postgres.py`). `run_full_load.py` is the production load and halts on any failure; `pipeline.py` has a `--dry-run`; `verify_full_load.py` checks results. Schema DDL is in `sql/` (numbered, apply in order). DB credentials come from `.env` (`POSTGRES_*`); scripts also fall back to `127.0.0.1` defaults. `local_pg_data/` and `backups/` are a local Postgres cluster and dumps.
2. **EDA** (`src/eda/`) → writes `reports/eda/`.
3. **Features** (`src/features/build_features.py`) builds a leakage-safe feature matrix; `export_ml_datasets.py` writes per-horizon datasets to `data/processed/ml/`. Leakage rules are in `reports/phase5_features/leakage_audit.md` — read before adding features. `build_feature_matrix(source=...)` has two modes: `"db"` (Postgres, 2025 only → `features_2025.parquet`) and `"offline"` (raw CSVs in `Og Data/` + `data/processed/recomputed_aqi.parquet`, 2024–2025, no Postgres needed). The 2023–2024 AQI target is **recomputed** from raw telemetry by `compute_cpcb_aqi.py` (CPCB method), because the official `aqi_hourly` table only covers 2025; rows carry `aqi_source` = `official` | `recomputed`.
4. **Modeling** (`src/models/`): baselines, LightGBM for 1h/6h (`models/lgb_model_*`), and a 50/50 Ridge + persistence hybrid for 24h (`models/24h/final/`, refined in `phase_6c_refinement.py`). Trees cannot extrapolate beyond the training AQI max (~347), which is why 24h uses a linear blend and why raw calendar features (e.g. month) were removed. Training outputs land in `data/Artifacts/{1h,6h,24h}/` and `reports/modeling/`. Heavy training notebooks are generated by `scripts/generate_*_notebook.py` into `notebooks/` (run on Colab).
5. **Classification / alerting** (`src/models/phase_7_classification.py`, `src/analysis/cost_aware_threshold_analysis.py`) → `reports/classification/{1h,6h,24h}/classified_predictions.parquet`, `metrics/*.csv`, `episodes/*.csv`. **Causal** analysis (`src/analysis/diwali_causal_analysis.py`) → `reports/causal/`.

6. **Tier 2 experiments** (`docs/TIER_2/`, status table in its `README.md`; plan in `docs/history/IMPROVEMENT_PLAN.md`): `retrain_24h_extended.py` (train on 2024-01 → 2025-08), `src/evaluation/rolling_origin_backtest.py` (per-winter folds), `train_pm25_forecast.py` (raw PM2.5 target), `ablation_exogenous.py` + `src/features/exogenous_drivers.py` (Open-Meteo weather / NASA FIRMS fires; needs network, run via `notebooks/tier_2_colab.ipynb`), `train_quantile_forecast.py` (quantile + conformal intervals). Split windows, the 24h embargo and the calendar-feature rule live in `src/models/splits.py`; use `assign_split` / `training_rows` rather than re-deriving them. Each script chooses variants (calendar on/off, target form, iteration counts) on validation only. `T2_PROFILE` (`standard` default, `max`, `smoke`; see `src/models/tuning.py`) controls compute: non-standard profiles write to a `<profile>/` subfolder. The `max` profile has been run in Colab and did not beat `standard` on test (see `docs/TIER_2/README.md`). Training is heavy and the dev laptop is weak, so run it in Colab (`notebooks/tier_2_colab.ipynb`), not locally. These write to `reports/modeling/{24h,pm25,exogenous,probabilistic}/` and do **not** replace the frozen models the serving layers read.

Test split is the held-out winter window Nov 1 – Dec 31, 2025; timestamps are Asia/Kolkata. Validation is Sep 1 – Oct 31, 2025. Project rules: select thresholds/hyper-parameters on validation only (test is scored once), and always report skill against persistence — `aqi_value` is a 24h rolling average (lag-1 autocorr ≈ 0.998), so persistence is a very strong baseline.

**Headline metrics:** every MAE/RMSE/R² quoted in the README or docs must come from `reports/metrics/headline_metrics.{csv,md}`, generated by `python src/evaluation/build_metrics_table.py` — don't hand-type numbers.

7. **Tier 3 live pipeline** (`docs/TIER_3/`; start at its `README.md`, plan in `PLAN.md`): `src/live/` ingests hourly readings (OpenAQ / data.gov.in behind one interface, `config/live.toml`) into Supabase Postgres (`db/migrations/`, schema `aq`, `DATABASE_URL` / `DATABASE_URL_READONLY` from `.env`, never printed), recomputes AQI, and `src/live/forecast.py` serves the **live-consistent** products of `src/live/serving.py` (AQI 1h = rule-based window-update persistence from `src/live/rules.py`; AQI 6h/24h and PM2.5 1h/6h = models in `models/live/`, hash-checked against `config/live_model_hashes.json`; which run is `[forecast]` in `config/live.toml`, ADR 0006) through the same `compute_feature_frame` that built the training matrix. The frozen models stay in `src/live/models.py` for parity and reference rows. Parity: `python -m src.live.parity_live` (live products, `docs/TIER_3/parity_live_report.md`) and `python -m src.live.parity` (frozen, `docs/TIER_3/parity_report.md`). The live models need numpy 2 and lightgbm (the local venv must be reinstalled from the requirements files). In `.github/workflows/` the OpenAQ ingest (`:10`) and the WAQI shadow ingest (`:20`, into `aq.shadow_readings`, never read by forecasts or the API) are scheduled; forecast, score and deploy are manual (`workflow_dispatch`), and the forecast cron waits for a source under 3 h old for 24 h straight. On this dev machine set `FORCE_IPV4=1`. Do not feed Open-Meteo-filled weather to the models (`weather_fill = "none"`; the D1 audit in `reports/modeling/live_audit/` shows why).

## Serving layers

- **FastAPI** (`backend/app/`): read-only `GET /api/v1/*` over the live database (`DATABASE_URL_READONLY`, role `api_readonly`); `service.py` builds the responses, `repository.py` holds the SELECTs, `models.py` the camelCase contract. Every forecast is `ok`, `unavailable` with the job's reason, or `withheld` (PM2.5 24h); AQI 24h is labelled experimental and always carries plain persistence (ADR 0006). Image: `backend/Dockerfile`; deploy: `.github/workflows/deploy-backend.yml`, setup in `docs/TIER_3/AZURE_SETUP.md`. The old Streamlit app and file-serving `backend/main.py` are gone.
- **React frontend** (`frontend/`, TypeScript + Vite + Tailwind + TanStack Query + React Router, hand-built SVG charts): Delhi Air Forecast dashboard (Overview, Stations, Operations, Model health) from `docs/design/`. Its zod schemas (`frontend/src/api/schemas.ts`) mirror the API models (ADR 0008): per-station forecasts that are `ok`, `unavailable` with a reason, or `withheld`; no interval and no P(severe). It runs on sample data (`VITE_USE_MOCK=true`) unless pointed at the API; Vercel setup is `docs/TIER_3/VERCEL_SETUP.md`. Vite proxies `/api` to `http://localhost:8000`. **See `frontend/CLAUDE.md`** for the design source, token and styling rules.

## Commands

```bash
# Python env (a venv/ exists in repo root)
pip install -r requirements.txt          # root: ETL, EDA, modeling
pip install -r backend/requirements.txt  # API only

# Run the apps
uvicorn backend.app.main:app --reload --port 8000  # run from the repo root; needs DATABASE_URL_READONLY
cd frontend && npm install && npm run dev         # also: npm run build | lint | type-check | test

# ETL
python etl/pipeline.py --dry-run
python etl/run_full_load.py
```

Phase scripts are run directly (e.g. `python src/models/baselines.py`); `make help` lists the Makefile targets (test, lint, format, type-check, data, run-api, run-frontend); ruff and pytest are configured in `pyproject.toml`. Python is 3.11+ per README. Scripts that `import src.*` need the repo root on `sys.path`: run the Tier 2 scripts from the repo root as modules, e.g. `python -m src.models.train_pm25_forecast` or `python -m src.features.exogenous_drivers` (`build_features.py` also has a `sys.path` shim, so a direct run works, but it then needs the Postgres DB in `db` mode). The local `venv/` has **no LightGBM** (and PyPI may be blocked), so Tier 2 scripts use scikit-learn `HistGradientBoosting`; LightGBM training runs on Colab.

## Tests

`tests/` is a pytest suite (`pytest.ini` sets `testpaths = tests`): `test_alignment.py`, `test_cpcb_aqi.py`, `test_episodes.py`, `test_splits.py`, plus the Tier 3 live-pipeline tests (`test_live_*`, `test_ingest.py`, `test_forecast*.py`, `test_openaq.py`, `test_qc.py`, `test_backfill.py`, `test_feature_*.py`, `test_probe_sources.py`; all mocked, no network or database). `test_forecast_parity.py` and the 1h/6h checks skip when the git-ignored training files or LightGBM are missing.

```bash
./venv/bin/python -m pytest                              # all
./venv/bin/python -m pytest tests/test_cpcb_aqi.py       # one file
./venv/bin/python -m pytest tests/test_cpcb_aqi.py -k name   # one test
```

`pytest.ini` sets `pythonpath = .`, so bare `pytest` also works; `python -m pytest` is still the safest form.

These run on files already in `data/` and `reports/`, not Postgres. The frontend has its own Vitest suite: `cd frontend && npm test`.
