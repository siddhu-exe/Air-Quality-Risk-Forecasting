# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Delhi air quality risk forecasting: 1h/6h/24h AQI forecasts across 7 CAAQMS stations, CPCB/GRAP risk classification with cost-sensitive alert thresholds, and a Diwali-ban causal (ITS/placebo) analysis. The project is a sequence of phases (ETL → EDA → features → modeling → classification), each leaving artifacts on disk that later phases and the UIs consume. `README.md` has results and background; `docs/` and `reports/**/*.md` hold per-phase findings and specs.

## Pipeline and data flow

1. **ETL** (`etl/`): raw CPCB/DPCC spreadsheets in `Og Data/` → `discover.py` → `transform_caaqms.py` / `transform_aqi.py` (header mappings in `schemas.py`) → idempotent load into PostgreSQL 16 (`load_postgres.py`). `run_full_load.py` is the production load and halts on any failure; `pipeline.py` has a `--dry-run`; `verify_full_load.py` checks results. Schema DDL is in `sql/` (numbered, apply in order). DB credentials come from `.env` (`POSTGRES_*`); scripts also fall back to `127.0.0.1` defaults. `local_pg_data/` and `backups/` are a local Postgres cluster and dumps.
2. **EDA** (`src/eda/`) → writes `reports/eda/`.
3. **Features** (`src/features/build_features.py`) reads Postgres and builds a leakage-safe feature matrix; `export_ml_datasets.py` writes per-horizon datasets to `data/processed/ml/`. Leakage rules are in `reports/phase5_features/leakage_audit.md` — read before adding features.
4. **Modeling** (`src/models/`): baselines, LightGBM for 1h/6h (`models/lgb_model_*`), and a 50/50 Ridge + persistence hybrid for 24h (`models/24h/final/`, refined in `phase_6c_refinement.py`). Trees cannot extrapolate beyond the training AQI max (~347), which is why 24h uses a linear blend and why raw calendar features (e.g. month) were removed. Training outputs land in `data/Artifacts/{1h,6h,24h}/` and `reports/modeling/`. Heavy training notebooks are generated by `scripts/generate_*_notebook.py` into `notebooks/` (run on Colab).
5. **Classification / alerting** (`src/models/phase_7_classification.py`, `src/analysis/cost_aware_threshold_analysis.py`) → `reports/classification/{1h,6h,24h}/classified_predictions.parquet`, `metrics/*.csv`, `episodes/*.csv`. **Causal** analysis (`src/analysis/diwali_causal_analysis.py`) → `reports/causal/`.

Test split is the held-out winter window Nov 1 – Dec 31, 2025; timestamps are Asia/Kolkata.

## Serving layers

Both UIs read the **pre-computed files in `reports/`**, not the database or live models:

- **Streamlit** (legacy): `dashboard/app.py`, with `app.py` at root as the Streamlit Cloud entrypoint.
- **FastAPI** (`backend/main.py`): loads the Parquet/CSV files in `reports/` into an in-memory dict at startup and serves `/api/stations`, `/api/forecasts`, `/api/causal/diwali`, `/api/thresholds/{sweep,operating-points}`, `/api/episodes`, `/health`. If a file is missing, startup only logs the error and endpoints return 503 — so changing a report's path/name breaks the API silently.
- **React frontend** (`frontend/`, TypeScript + Vite + Tailwind + React Query + Zustand + Recharts): replaces the Streamlit dashboard. Vite proxies `/api` to `http://localhost:8000`. **See `frontend/CLAUDE.md`** for design-token and styling rules (follow `frontend/stitch_*/…/DESIGN.md`). Note that file lists `npm test`, but `package.json` has no test script.

## Commands

```bash
# Python env (a venv/ exists in repo root)
pip install -r requirements.txt          # root: ETL, EDA, modeling, Streamlit
pip install -r backend/requirements.txt  # API only

# Run the apps
streamlit run app.py
uvicorn backend.main:app --reload --port 8000     # run from repo root; paths resolve relative to backend/..
cd frontend && npm install && npm run dev         # also: npm run build | lint | type-check

# ETL
python etl/pipeline.py --dry-run
python etl/run_full_load.py
```

Phase scripts are run directly (e.g. `python src/features/build_features.py`); there is no Makefile or task runner. Python is 3.11+ per README.

## Tests

`tests/` is a handful of standalone scripts, not a configured suite (no pytest config):
`python tests/test_aqi_ts.py`, `python tests/test_aqi_timestamp_boundaries.py`, `python tests/test_bp.py`, `bash tests/test_db.sh` (needs Postgres), `python tests/validate_kaggle_export.py`. pytest should also collect the `test_*.py` files; run one with `pytest tests/test_bp.py`.
