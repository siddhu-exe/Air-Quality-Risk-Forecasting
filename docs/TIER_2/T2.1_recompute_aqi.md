# T2.1 — Recompute CPCB AQI for 2023–2024 and train on prior winters

**Fixes:** D7 — the trees could never predict above ~347 because training only
saw Jan–Aug 2025 and no winter peak.
**Status:** complete, with caveats from the post-review audit (section 9). The overall
recompute gate passed (MAE 9.38 < 10) but not in every period; the extended-training 24h
model is in the headline metrics next to the frozen one.

## 1. Why the model needed this

`aqi_hourly` only exists for 2025 and the split was:

| Split | Window | Winter peak? |
| :--- | :--- | :--- |
| train | 2025-01-01 .. 2025-08-31 | no (Jan/Feb 2025 winter dropped by the split) |
| val | 2025-09-01 .. 2025-10-31 | no |
| test | 2025-11-01 .. 2025-12-31 | yes |

The raw station telemetry in `Og Data/Delhi data` does cover 2023–2024, but it
has no AQI label, so we reconstruct one with the official CPCB method.

Raw coverage actually available offline:

| Year | Stations with raw data |
| :--- | :--- |
| 2023 | Dwarka-Sector 8 only |
| 2024 | all 7 stations |
| 2025 | all 7 stations |

So "prior winters" in practice means **Jan/Feb 2024 + Dec 2024** (all stations)
plus late-2023 winter for Dwarka only.

## 3. The CPCB algorithm

1. **Sub-index per pollutant** via the official breakpoint table, linear
   interpolation inside each band:

   | Pollutant | Unit | Bands (concentration → sub-index) |
   | :--- | :--- | :--- |
   | PM2.5 | µg/m³ | 0–30–60–90–120–250–500 → 0–50–100–200–300–400–500 |
   | PM10 | µg/m³ | 0–50–100–250–350–430–600 → 0–50–100–200–300–400–500 |
   | NO2 | µg/m³ | 0–40–80–180–280–400–600 → 0–50–100–200–300–400–500 |
   | SO2 | µg/m³ | 0–40–80–380–800–1600–2400 → 0–50–100–200–300–400–500 |
   | NH3 | µg/m³ | 0–200–400–800–1200–1800–2400 → 0–50–100–200–300–400–500 |
   | CO | mg/m³ | 0–1–2–10–17–34–50 → 0–50–100–200–300–400–500 |
   | O3 | µg/m³ | 0–50–100–168–208–748–1000 → 0–50–100–200–300–400–500 |

2. **Averaging windows:** CO and O3 sub-indices use an 8-hour rolling mean
   (≥6 valid hours); the other pollutants use the hourly value.
3. **Hourly AQI** = max sub-index, valid only with ≥3 pollutants present *and*
   at least one of PM2.5/PM10.
4. **Reported value** = 24-hour rolling mean of that hourly AQI (≥16 valid hours
   in the window), matching how the stored `aqi_hourly` series behaves.

The alternative convention (24h mean of the concentration, *then* sub-index)
scores worse against official 2025 (**MAE 11.24**) and is only reported for
transparency, not used for the target.

## 4. Validation against official 2025

Ground truth: the official station-level `aqi_hourly` xlsx for 2025.
Output: `reports/features/aqi_recompute_validation.md`, `.csv`.

| Metric | Value |
| :--- | ---: |
| Matched hours | 57,755 |
| MAE | **9.382** (gate < 10 ✅) |
| Median absolute error | 6.389 |
| Bias (recomputed − official) | +6.485 |
| Share within ±5 | 42.2% |
| Share within ±10 | 65.9% |

Per-station MAE ranges 6.15 (ITO) to 10.58 (Punjabi Bagh); monthly MAE is 5.8–15.0.

**Honest caveats** (also in the report): the residual bias is positive and
concentrated at high AQI, and the official series contains isolated glitches
(e.g. an official spike to 314 while raw PM2.5 is 28 µg/m³). The reconstruction
is good enough as a training target but is **not** a drop-in replacement for the
official series, which is why official values still win for all of 2025.

## 6. Retraining result

Architecture is held fixed (persistence + Ridge α=1000, 50/50 blend, same 49
feature "Set Refined") — only the training data window changes:

| Model | Train window | Test MAE | Test RMSE | Test R² | MAE skill vs persistence |
| :--- | :--- | ---: | ---: | ---: | ---: |
| Frozen 24h | 2025-01 .. 2025-08 | 34.11 | 44.80 | 0.365 | 0.110 |
| **Extended 24h** (24h embargo) | **2024-01 .. 2025-08** | **34.02** | **44.68** | **0.368** | **0.113** |
| Persistence | — | 38.34 | 50.75 | 0.185 | 0.000 |

Validation (unchanged window) also improves: hybrid MAE **28.80** vs persistence
**30.71** (R² 0.853 vs 0.825).

The gain is small — two extra winters of *reconstructed* labels help, but the
24h AQI signal is still dominated by the smoothed target and a strong
persistence baseline. The value of T2.1 is mainly that the training window now
contains a winter peak at all, which unblocks T2.2–T2.5.

All numbers come from `reports/metrics/headline_metrics.csv` and
`reports/modeling/24h/final/extended_training_metrics.json`.

## 7. Reproduce

```bash
# 1. recompute AQI for 2023-2024 and validate on 2025
./venv/bin/python src/features/compute_cpcb_aqi.py --years 2023 2024 --validate

# 2. build the extended feature matrix (offline, no Postgres needed)
./venv/bin/python -c "from src.features.build_features import build_feature_matrix; \
  build_feature_matrix(source='offline', output_path='data/processed/features_extended.parquet')"

# 3. retrain and refresh the headline table
./venv/bin/python -m src.models.retrain_24h_extended
./venv/bin/python src/evaluation/build_metrics_table.py
```

## 9. Post-review audit notes

Found while checking Tier 2 against `docs/IMPROVEMENT_PLAN.md` (details in `docs/TIER_2/TIER_2_AUDIT.md`):

- **Gate is period-dependent.** Overall MAE is 9.38, but by period it is **10.31 for Jan-Aug 2025**,
  7.98 for Sep-Oct and 7.26 for Nov-Dec (see `aqi_recompute_validation.md`). The gate passes overall
  because the winter months are easier; the labels for the 2024 non-winter months are noisier than the
  headline suggests. The winter months (the ones that matter for this model) are the most accurate.
- **Method choice is robust.** `rolling_subindex_mean` beats `concentration_mean` on Jan-Aug alone
  (10.31 vs 10.55), so choosing it with all of 2025 in view did not depend on the test months.
- **Bias correction does not help.** Isotonic-calibrating the recomputed AQI to official using Jan-Aug 2025
  only *worsened* the Sep-Dec hold-out MAE (7.62 -> 8.00), so the recomputed series is used as is.
- **Train/eval label overlap removed.** A training row issued in the final 24h before the validation window has
  its `t+24` label inside it. These rows are now dropped (24h embargo). Effect on the extended model:
  validation MAE 28.80 -> 28.80, test MAE 34.02 -> 34.02 (negligible, but the leak is closed).
