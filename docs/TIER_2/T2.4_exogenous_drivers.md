# T2.4 — Exogenous drivers (weather + fires) and ablation

**Goal:** test whether meteorology and upwind fire counts add skill to the 24h
forecast, and quantify each group with an ablation.
**Status:** done for weather (corrected script run in Colab on 2026-10-09; results below).
**Fires have not been run** (they need a free NASA FIRMS `MAP_KEY`); they are reported as
`not_run`, never as a copy of the baseline.

## What was built

- `src/features/exogenous_drivers.py`
  - **Open-Meteo ERA5** archive per station: temperature, relative humidity,
    precipitation, wind speed/direction (→ u/v), boundary-layer height, shortwave
    radiation, surface pressure.
  - **NASA FIRMS** VIIRS active-fire counts in a Punjab/Haryana box
    (73.5–77.8°E, 28.5–32.5°N), per day, lagged 1–3 days (optional, `--fires`).
  - Merges onto the feature matrix with causal lags/rolls plus a clearly labelled
    **oracle** value at `t+24` (perfect future weather: an upper bound only).
- `src/models/ablation_exogenous.py` — ablation over feature groups, selecting on
  validation, scoring test once.
- `notebooks/tier_2_colab.ipynb` — runs it end to end (weather needs internet).

### What the audit changed

| Problem in the first version | Fix |
| :--- | :--- |
| **Boundary-layer height is 100% missing before 2024-07-01** in the Open-Meteo archive, and was median-imputed, i.e. a constant for the first third of the training window. | Two panels: `full_no_blh` (train from 2024-01, BLH columns dropped) and `blh_window` (train from 2024-07-01, BLH included). |
| Only the frozen linear hybrid was used. A single linear model cannot show whether weather helps through interactions. | Two families: `ridge_hybrid` (the frozen 50/50 model) and `gbm_residual` (HistGradientBoosting on target − `aqi_curr`, added back to persistence). |
| The `+fires` rows were identical to baseline and looked like a result. | Fire groups are `not_run` when no `fire_*` columns exist. |
| No test score, so "does it help" was never answered on the held-out window. | Test is scored once, for the best deployable configuration on validation and its matched baseline, next to persistence. |
| The oracle group could win the selection. | The `+weather_oracle` group is never eligible for selection. |
| No embargo. | 24h embargo before validation. |

Known limitation: the station coordinates in `exogenous_drivers.py` are approximate
(hard-coded), and ERA5 is **observed/reanalysed** weather, not a forecast, so even the
causal groups assume weather is known at issue time only up to `t`.

## Results

Source: `reports/modeling/exogenous/ablation.{csv,md}`. Validation = 2025-09-01..10-31;
MAE in AQI points, lower is better. `Δ` is the change vs the matching baseline.

| Panel (train rows) | Family | Baseline val MAE | + weather (causal) val MAE | Δ MAE | Val RMSE: baseline → weather | + weather (oracle) val MAE |
| :--- | :--- | ---: | ---: | ---: | :---: | ---: |
| `full_no_blh` (94,146) | `ridge_hybrid` | 28.795 | 28.753 | −0.042 | 40.009 → 39.495 | 28.670 |
| `full_no_blh` (94,146) | `gbm_residual` | 29.529 | 29.514 | −0.015 | 40.390 → 38.704 | 28.323 |
| `blh_window` (65,494) | `ridge_hybrid` | 28.842 | 28.885 | +0.043 | 40.131 → 39.739 | 28.717 |
| `blh_window` (65,494) | `gbm_residual` | 29.904 | 29.172 | −0.733 | 40.181 → 38.260 | 28.308 |

Fire groups: `not_run` in every panel/family (no FIRMS key).

**Best deployable configuration on validation:** `full_no_blh` / `ridge_hybrid` /
`+weather_causal` (val MAE 28.753). Test was scored once, for it and its matched baseline:

| Config | Test MAE | Test RMSE | Test R² | MAE skill vs persistence |
| :--- | ---: | ---: | ---: | ---: |
| `ridge_hybrid` + weather_causal | 33.890 | 44.52 | 0.373 | +0.116 |
| `ridge_hybrid` baseline (same as the extended model) | 34.018 | 44.68 | 0.368 | +0.113 |
| Persistence | 38.342 | 50.747 | 0.185 | 0 |

## Interpretation

- **Causal weather barely moves the 24h point forecast.** On the winner, test MAE improves by
  0.128 AQI points (0.4%), far smaller than the ±4–5 point day-block CI on the test MAE itself
  (the CI of the *difference* was not computed, so this is not a demonstrated improvement).
  The skill moves from +0.113 to +0.116.
- **Weather helps the large errors more than the typical error.** RMSE falls in every panel and
  family (e.g. 40.39 → 38.70 and 40.18 → 38.26 for the GBM), while MAE changes by under 0.05
  except for the GBM in the `blh_window` panel (−0.733).
- **The GBM only becomes competitive with weather.** Its baseline is worse than the Ridge hybrid
  (29.5–29.9 vs 28.8 val MAE), and even with causal weather it stays above the Ridge hybrid on
  MAE (29.17 at best) while having better RMSE. So the linear model remains the better
  deployable choice on MAE, which is why validation selected it.
- **Boundary-layer height did not help the linear model** (+0.043 MAE) and its panel trains on
  a third fewer rows; it only helped the GBM, where the panel baseline is also worse, so the
  gain is partly an artefact of a weaker baseline.
- **Perfect future weather (oracle) is an upper bound, not a result:** it gives −1.2 to −1.6 MAE
  for the GBM and about −0.13 for the Ridge hybrid. That caps what a real forecast could add and
  shows the signal is mostly nonlinear.
- Net: weather is a modest, mostly-tail (RMSE) improvement at 24h, not a step change. The next
  test would be real forecast weather (GFS/ECMWF), a paired bootstrap on the MAE difference, and
  a probabilistic evaluation (T2.5), where tail errors matter more.

### Max-compute check (`T2_PROFILE=max`, Colab, 2026-10-10)

Source: `reports/modeling/exogenous/max/ablation.{csv,md}`. The GBM hyper-parameters were tuned on each panel's
baseline group (validation only); everything else is as above.

- **Best deployable on validation changed** to `blh_window` / `gbm_residual` / baseline (val MAE 28.528, vs 28.753 for
  the standard pick). The margin over the Ridge hybrid is only about 0.2 MAE.
- **Test (scored once) is worse:** MAE 34.505 (RMSE 45.05, R² 0.358) vs 33.890 for the standard pick and 34.018 for the
  Ridge baseline; persistence 38.342. Tuning the GBM on the calm validation window did not transfer to the winter.
- **With the tuned GBM, weather no longer helps on validation** (+0.38 MAE causal, +0.14 in `blh_window`), so the
  earlier GBM weather gains came from a weaker untuned baseline.
- **The `+fires` rows are not evidence.** The Colab feature file had four `fire_*` columns (53 features), yet the Ridge
  MAE is identical to baseline, so the columns carry no signal (no FIRMS key was used; they are probably empty or
  constant). The GBM's small differences there come from `max_features=0.7` sampling a different column set. Fires remain
  not run. The feature file was not available locally, so this was not checked directly.

The accepted standard results above are unchanged.

### Superseded

The first version of this ablation reported flat validation MAE (28.801 → 28.804 causal, 28.695
oracle) with imputed boundary-layer height, a single linear model and fire rows copied from the
baseline. Those numbers are not comparable to the table above and should not be quoted.

## Reproduce

```bash
# needs internet
python -m src.features.exogenous_drivers --start 2024-01-01 --end 2025-12-31
# optional, needs FIRMS_MAP_KEY
FIRMS_MAP_KEY=xxxx python -m src.features.exogenous_drivers --start 2024-01-01 --end 2025-12-31 --fires
python -m src.models.ablation_exogenous       # run in Colab
```
