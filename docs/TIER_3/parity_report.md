# Forecast-path parity with the stored backtest predictions

Tolerance: 1e-06 (absolute, AQI units). Generated by `python -m src.live.parity`; numbers come from `parity_report.csv`.

Sampled issue hours (random, plus first/last/day-edge hours) are pushed through the production functions (`to_inputs` -> `build_frames` -> `models.predict`) from history reshaped like the database tables, and compared with the stored predictions. Predictions only: no error against actuals is computed, so nothing here re-scores the test window.

`live path` = what the hourly job does (a ~17-day history window). `rolling from training start` = the same code with the rolling windows started where training's started (2024-01-01), a diagnostic: pandas' rolling mean/std are online algorithms, so their last digits (about 1e-10) depend on where the window began, and on a few rows that flips a LightGBM split sitting exactly on a threshold. Where the two variants differ, the model, the features and the code path are the same and only that noise remains.
